# Выкладка на YouTube (YouTube Studio через bsk)

Всё outward-изменение YouTube — **только** через `scripts/publish_studio.mjs`
(ручные клики в браузере — только для диагностики/спасения, см. «Отказы»).
Правила безопасности прогона: ≤5 загрузок за прогон; работать в один поток
(последовательно, без конкурирующих прогонов); при капче/подозрительном
поведении — звать человека, не гадать.

## Предусловия

1. bsk-демон запущен отдельным процессом: `~/.local/bin/bsk.exe daemon start --foreground`
   (detached-запуск может не выходить; все bsk-вызовы с `BSK_AUTO_START=0`).
2. В Chrome стоит расширение BrowserSkill с включённым local connection,
   и залогинен **нужный** Google-аккаунт канала (см. «Каналы»).
3. Проверка: `node scripts/publish_studio.mjs check` (не залогинен → `request-help`,
   дописывает человек).

## Файлы

| файл | что |
|---|---|
| `data/youtube.json` | очередь шортсов: `order[]`, `videos.<id>` = `{file,title,description,tags[],publishAt?,publishNow?,channel?}` |
| `data/upload_state.json` | состояние шортсов; `isDone` = status `scheduled`\|`published` — их дайст не берёт (идемпотентность) |
| `data/weekly_state.json` | длинные: `episodes[]` (плюс `thumb?`, `thesis`) + `episodeState{}` |
| `.tmp-pub/publish.log` | журнал всех прогонов; `…__FAIL.png`, `…__QUOTA.png` — диагнозы |

Правила содержимого: описание **≤100 символов** (2–3 поисковых ключа + вопрос
в комменты); `publishAt` — ISO `+03:00` (per-video, в обход дайджестовых
слотов); «Место съёмки = United States» — задавать в каждое видео.

## Команды

```
node scripts/publish_studio.mjs check                      # логин/канал
node scripts/publish_studio.mjs status                     # залито N/M, очередь, слоты
node scripts/publish_studio.mjs publish [--only=id] [--limit=N] [--dry] [--slot-offset=K]
node scripts/publish_studio.mjs publishweekly [--only=id] [--dry]
```

- Слоты по умолчанию: завтра, 8/11/14/17/20 фикс. UTC+3; занятые слоты
  (по `publishAtLocal` в state) пропускаются, шаг вперёд по дням.
- `--dry` — заполнить поля и расписание, **не** сохраняя (проверка формы).
- `publishweekly` берёт **один** самый старый незапланированный эпизод;
  длинные 1080p грузятся дольше (паузы up 90–120 с, proc 150–200 с).
- Любой FAIL = стоп дайста + скриншот `<id>__FAIL.png` + строка в publish.log.

## Как проходит загрузка (для отладки)

1. Контент → «Добавить видео» (или «Создать»→menuitem; после смены аккаунта
   `/content` может отдать кэш «нет доступа» → скрипт сам уходит на home студии
   и жмёт «Создать»/«Добавить видео» теневыми кликами). Прямой upload-URL Studio
   не использовать (рвёт в ошибку).
2. `upload` на drop-zone. Появилось «Загрузка недоступна» → суточный лимит
   канала: **не повторять в тот же день**, сообщить человеку (квота или
   «Пройти проверку»).
3. Детали: `input#title` → описание `yt-formatted-string#description`
   (фокус ставится DOM-ом сквозь shadow DOM, длина сверяется; молчаливый дубль
   в «Название» — известная поломка, валиться при расхождении длины) →
   «Показать дополнительные настройки» → «Теги» (каждый тег + реальная
   запятая `,` = чип) → миниатюра (shadow-хак `input#file-loader`, приёмка —
   `<img>` ytimg в аплоадере) → «Место съемки» → COPPA-радио
   «Нет, это видео не для детей». **Escape в модалке загрузки не нажимать** —
   закрывает всё модальное окно.
4. Экран «Доступ»: радиокнопки `Ограниченный доступ` / `Доступ по ссылке` /
   `Открытый доступ` (в списке Контента они же — «Для всех» / «По ссылке»).

## Публикация

**По расписанию (по умолчанию).** До «Доступа» — степпер «Далее»; виджет
«Запланировать публикацию»: кнопка даты (RU-формат «29 окт. 2026 г.»; машина +3,
по умолчанию «завтра») → при несовпадении открыть календарь и вписать дату в
`textbox` поля даты → Enter; время — `textbox "00:00"` (24 ч, печатать с
Control+a, сверить, что поле приняло). Submit — **кнопка** «Запланировать
публикацию» (последний hit VOM; ссылка «Подробнее…» с тем же текстом в [ctx:]
открывает Справку — лишний таб `support.*` закрывать). Подтверждение — диалог
«Публикация видео запланирована». В state: `status:"scheduled"`, videoId, время.

**Немедленно (`publishNow: true`).** На «Доступе» — радиокнопка «Открытый
доступ» и кнопка «Опубликовать» сидят в **shadow DOM** (observe слеп) — жмутся
через `evaluate`; кнопка может прятаться за «Обработка занимает больше
времени…» — ждать до 120 с. Премьера («Назначить премьеру» / «Провести
премьеру сейчас») в UI есть, но не автоматизирована.

**Ложные диалоги:** текст после submit врёт в обе стороны (бывал ложный
«Видео опубликовано» у FAIL и ложный «нет ряда» при успехе). Истина — страница
сведений / ряд в Контенте: «Отложенная публикация» + дата/время, или факт
доступности видео. Перед записью статуса сверяй рядом/скриншотом.

## Плейлисты (проверено живым read-only зондом 29.10.2026)

Автоматизации в скрипте **нет** — только через UI (bsk вручную):

- **Добавить видео в плейлист при загрузке/правке:** экран «Детали» (и «Сведения»
  у опубликованного) → секция «Плейлисты» → кнопка `button "Выбрать плейлисты"`
  → чекбоксы нужных плейлистов. Правка полей опубликованного квоту не тратит.
- **Страница плейлистов:** Контент → tab «Плейлисты»; честный URL —
  `https://studio.youtube.com/channel/<CH>/content/playlists`
  (deep-link `/channel/<CH>/playlists` отдаёт «Произошла ошибка» — не работать
  с ним; вход через боковой tab или navigate на /content сначала).
  Колонки: Плейлист / Тип / Доступ («Для всех», «По ссылке») / изменение / видео / просмотры.
- **Создать плейлист:** верхняя кнопка «Создать» → menuitem `Создать плейлист` →
  диалог «Новый плейлист»: `textbox "Введите название"` (обязательное),
  `textbox "Добавьте описание"`, `button "Параметры доступа …"` (Открытый
  доступ / по ссылке / частный), `button "Порядок видео по умолчанию …"`,
  `button "Добавить видео"`; кнопка `Создать` задизейблена до названия.
  Закрытие — `button "Закрыть"` (не «Отмена») или уход navigate.

## Каналы и переключение аккаунтов

| канал | id | аккаунт |
|---|---|---|
| основной (EN; шортсы по умолчанию) | `<EN_CHANNEL_ID>` | основной Google-аккаунт (логин в профиле Chrome, не в git) |
| второй (RU) | `<RU_CHANNEL_ID>` | вторая учётка того же Chrome |

Канал выбирается данными: `videos.<id>.channel` / `episodes[].channel`
(дефолт — значение `channel` из `data/youtube.json`). **В браузере должен
активироваться соответствующий Google-аккаунт** — сам скрипт аккаунт не
переключает. Переключение вручную: аватар канала → «Сменить аккаунт» →
строка нужного канала (клик полной последовательностью pointer/mouse-событий);
верификация — открытие `/content` канала с видео-рядами. Признак неверного
аккаунта: «У вас нет доступа к этой странице» / 403 на канальем URL
(держать read-only диагностик: кто залогинен + пробы /content обоих каналов).

## Отказы и спасение

- **FAIL дайста** = обычно видео уже залито **черновиком**: спасатель черновика
  («Редактировать черновик» со скролл-поиском → «не для детей» → «Доступ» →
  Открытый доступ → дата/время → submit; сверка рядом). Держать такой скрипт
  отдельно, publishAt он берёт из `youtube.json`.
- Повторный дайст идемпотентен (isDone), но при ложном FAIL без state-записи
  видео зальётся повторно — после ручного спасения самому записать
  `{status:"scheduled", videoId, publishAtLocal, publishAtET}` в state.
- Капча / «Пройдите проверку» / странный диалог — стоп, человек.
- Рабочий каталог инструментов (`.tmp-pub/`) и профиль браузера в git не коммитить.

## Чеклист после дайста

1. `status`: нужные id стали `scheduled`/`published`.
2. Для каждого — скриншот `__scheduled.png`/`__published.png` с честным
   подтверждением (или ряд «Отложенная публикация»).
3. `videoId` заполнен; описание ≤100; «Место съемки» = United States
   (лог `✓ «Место съемки»`); теги чипами; COPPA «не для детей».
4. weekly: статус продублирован в `weekly_state.json` (`episodes[].status`).
